# .NET 10 Modernization - Design

## Problem

The repo targets `net9.0` while the only SDK/runtime installed on the dev
machine is .NET 10 (hence the `DOTNET_ROLL_FORWARD=LatestMajor` workaround
threaded through the gate). Packages are stale (xunit 2.9.2, runner 2.8.2,
Test.Sdk 17.12.0, coverlet 6.0.2) and version-pinned per-project. The agent
instruction stack is split across `CLAUDE.md` (style authority, injected via
`opencode.json` `instructions`) and `AGENTS.md`; every consumer of the former
already reads the latter, so the split is pure drift cost. Solution format is
the legacy `.sln`.

## Scope

In scope:

- Retarget all 8 projects `net9.0` -> `net10.0`.
- Update the 4 direct test packages to the latest versions the sandbox probe
  verified (xunit 2.9.3, xunit.runner.visualstudio 4.0.0,
  Microsoft.NET.Test.Sdk 18.10.1, coverlet.collector 10.0.1).
- Pin dependencies: Central Package Management (`Directory.Packages.props`)
  for versions, per-project `packages.lock.json`, `global.json` pinning SDK
  10.0.101.
- Migrate `AsteropeDb.sln` -> `AsteropeDb.slnx` via `dotnet sln migrate`, add
  `.slnx` to the solution-documentation file types in `.editorconfig`/Rider
  settings, and retire the Rider `Build_Solution` run configuration.
- Delete `CLAUDE.md` and consolidate: AGENTS.md becomes the single style
  authority; update `opencode.json`, all `.opencode/prompts/*.md`, and
  `PRD.md:244` so nothing references the deleted file; replace the obsolete
  roll-forward gate text with the new `dotnet test AsteropeDb.slnx` gate.
- Update PRD.md's ".NET 9" runtime facts to ".NET 10" (via this spec — PRD
  edits are tripwired to the spec path, which this is).

Out of scope (deliberately):

- xunit v3 migration. Latest v2 line is a compatible, boring bump; v3 is a
  package-identity change with test-API churn. Separate decision, separate
  cycle.
- StyleCop.Analyzers version change. 1.2.0-beta.556 *is* the latest release;
  there is nothing to update to.
- The pre-existing SA1649 warning in `src/AsteropeDb.Core/IDbType.cs` (known,
  tracked in AGENTS.md; not this cycle's job).
- New dependencies (MessagePack, anything). None exist yet; nothing to
  migrate.
- Content changes to CLAUDE.md's style rules — they move verbatim into
  AGENTS.md, they are not being rewritten.
- `README.md` — contains no net9/CLAUDE/sln references (verified); no edits
  needed.
- `PRD.md.bak` removal — stale tracked copy; AGENTS.md says never reference
  it, and deleting it is its own small cycle.

## Approach

A single modernization pass over build shape + dependency pinning + agent
config, executed as one Track L plan. The move that makes this safe: the
target state (net10.0 + CPM + latest packages + slnx) was reproduced and gated
green in a sandbox copy of the repo *before* anything was committed. Every
version in the plan is therefore verified, not assumed.

No tests will be written for this change. It is a build-system and
documentation-only change: the gate itself (build + 129 green tests) *is* the
test, and no test could observe the difference between `.sln` and `.slnx`,
pin versions, or a deleted markdown file. This is the AGENTS.md "no test could
observe the difference" exemption.

## Approach alternatives considered

- **Per-project version bumps only, no CPM/locks**: smallest diff, but leaves
  versions to drift out of sync between the four identical test csprojs — the
  exact failure "pin dependencies" exists to prevent. Rejected.
- **Single repo-level `packages.lock.json`**: `--use-lock-file` supports
  central-lock mode, but a central lock breaks down as modules become NuGet
  packages with independent restore inputs. Per-project locks are the
  documented, composable default. Rejected.
- **Delete CLAUDE.md, absorb nothing**: loses the style rules and leaves
  dangling references in five files. Rejected.
- **Keep CLAUDE.md and just add AGENTS.md**: the status quo — the two files
  already disagree (AGENTS.md asserts net9, CLAUDE.md asserts .NET 9 runtime
  facts) and drift is guaranteed. Rejected.

## Contracts

### Build files (new)

```
global.json                      { "sdk": { "version": "10.0.101",
                                          "rollForward": "latestPatch" } }
Directory.Packages.props         <PackageVersion> for the 5 packages below
packages.lock.json               one per project, generated by dotnet restore
AsteropeDb.slnx                  generated by `dotnet sln migrate`, then
                                 verified (8 projects, 2 folders)
```

### File-type registrations

- `.idea/runConfigurations/Build_Solution.xml`: deleted. It points at the
  removed `AsteropeDb.sln`; a stale run configuration is a booby-trap.
- `.editorconfig` and `.idea` gitignores: no changes needed (verified — no
  solution-file sections exist to update).

### Agent config (existing files, modified)

- `opencode.json`: `"instructions": ["CLAUDE.md"]` removed (AGENTS.md is
  auto-loaded). `"CLAUDE.md": "allow"` removed from orchestrator edit
  permissions. `"dotnet build AsteropeDb.sln*"` and the roll-forward test
  entry in the reviewer bash allowlist rewritten for `.slnx` / bare
  `dotnet test`.
- `AGENTS.md`: becomes the self-contained style authority (CLAUDE.md's code
  style + project overview absorbed); roll-forward explanation replaced by
  the .NET 10 reality; solution references renamed to `.slnx`; gate command
  rewritten.
- `PRD.md`: line 244 (`CLAUDE.md with development guidelines`) ->
  `AGENTS.md`; the `.NET 9` runtime facts -> `.NET 10` (101, 171, 190, 218,
  223, 234, 371).
- `CLAUDE.md`: deleted.
- `.opencode/prompts/`: roll-forward text replaced by the new gate in
  `coder.md`, `reviewer.md`, `orchestrator.md`, `cmd-gate.md`, `cmd-plan.md`,
  `cmd-fix.md`, `cmd-small.md`, `cmd-tdd.md`, `cmd-review.md`, `cmd-design.md`;
  CLAUDE.md references replaced by AGENTS.md.

## Failure modes

- **Slnx not understood by a consumer**: covered — verified with `dotnet
  build`, `dotnet test`, `dotnet list`, `dotnet sln list`. Rider is retired
  via the run-config deletion. If VS/Rider support matters later, re-adding a
  `.sln` is a one-command operation — low reversal cost.
- **Lock-file churn**: restore is the only path that updates lock files;
  verification is the diff. Contained in step 3.
- **Styling drift after CLAUDE.md deletion**: mitigated — its rules move
  verbatim into AGENTS.md, which is auto-loaded by opencode and read by
  Claude; `instructions` in opencode.json becomes redundant and is removed.
- **Breaking change in a bumped package**: mitigated — the versions are
  resolved and gated in the sandbox before real use; a failing bump is caught
  at the plan gate, not in production.

## Testing strategy

The gate is the test. Build must succeed with 0 warnings (the one known SA1649
exception tracked in AGENTS.md), and `dotnet test AsteropeDb.slnx` must report
129/129 (126 Core + 3 placeholders). Steps that only touch docs/config have
no test to write; steps that touch build files are gated by build+test on the
real tree.

## Rejected alternatives

- xunit v3 migration: package-identity change, out of scope, separate cycle.
- Central lock file: breaks composability when modules become packages.
- Keeping `.sln` alongside `.slnx`: two solution files that can drift apart —
  the very problem being removed.
- Leaving PRD.md's CLAUDE.md/.NET 9 references: dangling reference to a
  deleted file and stale design facts; the spec is the sanctioned path for
  PRD edits.

  carries .NET 10, the slnx structure and central package management, and has
  no CLAUDE.md references. Two session facts were added back to the M0 row:
  lock files and the `global.json` SDK pin.

  instead of memory-mapped files, MVCC single-writer, HTTP+gRPC, clustering

  untracked local copy, not a tracked one).
